# СтройНорм РФ

Telegram-бот для поиска по строительным СП и ГОСТам РФ и подготовки ответов с цитатами на документ, пункт и страницу.

## Возможности

- бесплатный локальный гибридный поиск по словам, тематике, склонениям и частым опечаткам;
- тематическая маршрутизация любого строительного вопроса по областям применения всех 81 документов реестра;
- отдельная проверенная база из 92 численных требований с условиями применения, способом контроля, пунктом и официальной ссылкой;
- поиск по загруженным PDF/TXT/MD документам и проверенному реестру нормативов;
- ответы только по найденным фрагментам;
- ссылки на официальный источник, документ, пункт и страницу, когда они присутствуют в базе;
- автоматический локальный ответ, если OpenAI API не подключён, недоступен или не оплачен;
- предупреждение о необходимости проверки актуальной официальной редакции;
- webhook-режим для Render и polling-режим для локальной разработки.

В реестре собраны ключевые действующие документы по автомобильным дорогам, мостам, организации строительства,
конструкциям, основаниям и фундаментам, пожарной безопасности, зданиям, инженерным системам, отделочным работам,
строительной физике, изысканиям и проектной документации. Для закрытых или платно распространяемых текстов бот
хранит только проверенную карточку и официальный адрес, но не копирует текст документа.

## Переменные окружения

- `TELEGRAM_BOT_TOKEN` — токен от BotFather;
- `OPENAI_API_KEY` — необязательный ключ OpenAI API; без него работает бесплатный локальный ответ;
- `OPENAI_MODEL` — модель интеллектуального ответа, по умолчанию `gpt-5.6-luna`;
- `PUBLIC_URL` — публичный адрес Render, например `https://stroynorm-bot.onrender.com`;
- `WEBHOOK_SECRET` — произвольная длинная случайная строка;
- `ADMIN_TELEGRAM_ID` — необязательный Telegram ID администратора.

## Загрузка нормативов

Поместите легально полученные документы в `data/documents/`, затем выполните:

```bash
python -m scripts.ingest data/documents
```

Индекс будет создан в `data/stroynorm.db`. Для распознанного обозначения документа в индекс также сохраняются
официальная ссылка и сведения о редакции. PDF должен содержать текстовый слой; для сканов предварительно требуется OCR.

Полные тексты следует загружать только из официальных или разрешённых источников. Наличие карточки документа в
реестре не означает, что его полный текст уже проиндексирован: точные пункты, страницы и численные нормы бот выводит
только из фактически загруженного текста.

Даже без отдельного SQLite-файла бот ищет по названиям, областям применения и профессиональному словарю всех
документов реестра. Такой результат помечается как подбор применимых документов. Он содержит официальные ссылки,
но не превращается в численную норму, пока соответствующий пункт не добавлен в проверенную полнотекстовую базу.

Проверенные численные требования из `data/requirements.json` являются исключением: они вручную сверены с указанной
редакцией и выводятся до полнотекстового поиска. Если параметр неоднозначен, запись должна содержать все применимые
варианты и условия, а не одно усреднённое число.

Для требований с заранее опубликованной датой изменения поддерживаются границы действия. После истечения срока
карточка перестаёт выдавать прежнее число до повторной сверки, поэтому будущая редакция не подменяет действующую.

## Локальный запуск

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python -m app.main
```

## Важно

Бот является справочным инструментом. Перед проектированием и строительством необходимо проверять статус и текст документа в официальном источнике.
